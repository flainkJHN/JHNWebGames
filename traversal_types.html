1. Finding the Shortest Path in an Unweighted Graph

DFS Approach:

Imagine a railway network: 

London
├── Cambridge
│   ├── Norwich
│   └── Ipswich
└── Peterborough
    └── York

A Depth First Search would choose one branch and continue exploring that branch as deeply as possible. It might travel:

London → Cambridge → Norwich

before checking any other stations. It could spend a long time exploring routes that do not contain York before eventually backtracking and trying another route.

BFS Approach:

A Breadth First Search would explore every station one stop away from London first: 

Level 1:
Cambridge
Peterborough

Level 2:
Norwich
Ipswich
York

The first time York is discovered, BFS knows it has found the route with the fewest edges (stops).

2. Solving a Maze

DFS Approach:

Imagine entering a maze and always choosing one path until you cannot continue.

DFS would follow a route until it reaches:

  • The exit
  • A dead end

If it reaches a dead end, it backtracks to the previous junction and tries another path. 

Start
  ↓
  ↓
Junction
  ↓
  ↓
Dead End

This mirrors how many humans naturally solve mazes.

BFS Approach:

BFS would investigate every possible route one step from the start, then every route two steps away, then every route three steps away.

This guarantees the shortest route through the maze but potentially requires storing thousands of positions simultaneously.

3. Searching a Family Tree by Generation

DFS Approach:

Suppose you are researching your ancestors. 

You
└─ Parent
   └─ Grandparent
      └─ Great Grandparent

DFS would follow one side of the family tree as deeply as possible. It might investigate your father's family for five generations before returning and beginning to examine your mother's side.

BFS Approach:

BFS naturally searches generation by generation. 

Generation 1:
Parents

Generation 2:
Grandparents

Generation 3:
Great Grandparents

This makes BFS ideal if your goal is to discover everyone at a particular generation level.

4. Exploring Possible Moves in a Puzzle Game

DFS Approach:

Imagine a puzzle where each move creates several new possibilities.

DFS may try: 

Move A
 → Move C
   → Move H
     → Move R

It continues exploring a single sequence of moves until it finds a solution or reaches a dead end.

Because only the current path needs to be remembered, memory usage remains relatively low.

BFS Approach:

BFS would store every move available at each level: 

Depth 1:
A B C

Depth 2:
D E F G H I J K

Depth 3:
Many more possibilities...

While BFS guarantees the shortest solution, memory requirements can become enormous.

5. Social Media Friend Suggestions

DFS Approach:

Suppose your direct friends are: 

You
├─ Alice
├─ Bob
└─ Charlie

DFS might investigate: 

Alice
 → Dave
   → Emma
     → Fred

before even considering Bob or Charlie.

This means suggestions may be based on quite distant connections.

BFS Approach:

BFS naturally explores: 

Level 1:
Friends

Level 2:
Friends of Friends

Level 3:
Friends of Friends of Friends

Because people are more likely to know friends-of-friends than connections several layers away, BFS usually produces better recommendations.

6. Finding a File Deep Inside a Folder Structure

DFS Approach:

Suppose your computer contains: 

Documents
├─ School
│  ├─ OCR
│  │  └─ Revision.docx
│  └─ Resources
└─ Photos

DFS would immediately explore: 

Documents
 → School
   → OCR
     → Revision.docx

before returning to investigate other folders.

If files are usually buried deep within nested folders, this is often efficient.

BFS Approach:

BFS would first search: 

Documents
├─ School
└─ Photos

Then all folders inside those locations before going any deeper. It may spend a lot of time checking folders that do not contain the target file.
